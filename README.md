# Planner

Planner — личное приложение для планирования дня и учёта дел. В нём есть календарь, проекты и подзадачи, таймер работы, финансы, тренировки, обучение и портфолио. Приложение работает в браузере и может устанавливаться как PWA. Данные хранятся на устройстве; после входа в аккаунт доступна синхронизация через Supabase.

## Технологии

- HTML, CSS и JavaScript без сборки.
- Service worker и web manifest для установки и работы без сети.
- Supabase для авторизации и синхронизации.
- Node.js 22+ для локального запуска; Docker и Nginx — для запуска в контейнере.

## Структура проекта

| Путь | Назначение |
| --- | --- |
| `frontend_ts/public/` | Готовое приложение: HTML, JavaScript, CSS, изображения и файлы PWA. |
| `frontend_ts/scripts/` | Локальный HTTP-сервер. |
| `frontend_ts/tests/` | Автоматические проверки. |
| `backend/` | Описание серверной части на Supabase. |
| `nginx/` | Конфигурация веб-сервера для Docker. |
| `docs/` | История версий и технические документы. |

## Локальный запуск

Из корня проекта:

```bash
node frontend_ts/scripts/serve.mjs
```

Откройте [http://localhost:8080](http://localhost:8080). Для остановки сервера нажмите Ctrl+C. Установка пакетов не требуется.

## Запуск через Docker

Из корня проекта:

```bash
docker compose up --build -d
```

Приложение будет доступно по адресу [http://localhost:8080](http://localhost:8080). Для остановки:

```bash
docker compose down
```

Docker-конфигурация открывает локальный HTTP-порт 8080. Для собственного публичного домена настройте HTTPS на сервере.

## Публикация

Разместите **всё содержимое `frontend_ts/public/` вместе с подкаталогами** в каталоге сайта. Приложение использует относительные пути, поэтому может работать как в корне домена, так и в подкаталоге, например `/planner/`. Для установки PWA на публичном сайте нужен HTTPS.

Для переноса данных между адресами или браузерами используйте экспорт и импорт JSON в настройках Planner. Локальные данные браузера автоматически на другой адрес не переходят.

## Проверка

Из корня проекта:

```bash
node --test frontend_ts/tests/assets.test.mjs
```

Браузерные сценарии запускаются командой `node frontend_ts/tests/browser-audit.mjs`; для них нужны Playwright и установленный Chrome. Они используют отдельный профиль браузера и локальный сервер на порту 8080.
