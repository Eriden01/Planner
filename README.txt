Planner v0.9.46 — мобильный аудит

МОБИЛЬНЫЕ ИСПРАВЛЕНИЯ
Редакторы учитывают VisualViewport и экранную клавиатуру. Нижняя навигация
скрывается во время ввода при открытой клавиатуре; масштабирование доступно.
Сенсорные устройства сохраняют мобильный режим и после поворота экрана.
Календарные обработчики обновляются при изменении режима без сброса форм.
Маленькие кнопки увеличены до 44×44 px, формы лучше помещаются на узком экране.
В Настройках доступен запрос устойчивого хранения. Решение принимает браузер;
отказ не удаляет данные. Экспорт и синхронизация остаются необходимыми.
Офлайн HTML-фallback применяется только к страницам, а не к изображениям.
20 наборов проверок используют DOM/сервисные модели. Настоящие iPhone,
Android, Safari и Chrome на устройствах, установка PWA и системная клавиатура
не проверялись. Полная совместимость на каждом телефоне не подтверждена.
Подробности: отдельный отчёт Mobile-audit-v0.9.46.md.

ТЕМЫ
В Настройках доступны четыре варианта: Системная, Тёмная, Светлая, Бежевая.
Бежевая заменила пустую плашку «Кастомная» и доступна всем пользователям.
Она использует кремовый фон, песочные поверхности, коричневые акценты
и тёмный текст. Палитра применяется к меню, всем страницам, формам и диалогам.
Категории календаря сохраняют выбранные пользователем цвета.
Профиль больше не остаётся бежевым в тёмной или светлой теме.
Системная автоматически следует настройке устройства, явные темы — нет.
Выбор сохраняется на устройстве и обновляется между открытыми вкладками.
Записи планера и настройки категорий при смене темы не меняются.

ПРОФИЛЬ ПО УТВЕРЖДЁННОМУ КОНЦЕПТУ
Крупное фото пользователя, тёплая палитра, имя с лавровыми ветвями,
объёмные изображения папки, книг, рамки, блокнота и календаря.
Графика встроена в HTML: дополнительные файлы на сайт загружать не нужно.
Результаты берутся из существующих данных, демонстрационные цифры не добавлены.
Завершёнными считаются проекты и цели с хотя бы одной подзадачей,
когда все подзадачи выполнены. Архивированные результаты учитываются.
Перенесённые цепочки не дублируют прогресс. Постоянная работа не считается
завершённым проектом. Обучение считает подтверждённые этапы, портфолио —
работы со статусом «Готово». В фокусе — первый незавершённый навык,
либо активный проект. Карточка открывает соответствующее направление.
Недели переключаются назад до любого периода, вперёд — до текущей недели.
Время берётся из записей таймера; выполненные задачи — из completedAt.
Старые записи без даты завершения не приписываются к текущей неделе.
Последние результаты показывают проверенные этапы и обновления готовых работ.
Имя и фото редактируются только в Настройках. Новые фотографии сохраняются
до 512×512 с прежним ограничением размера; при необходимости уменьшаются.
Старые маленькие фото не станут чётче автоматически: выберите исходник заново.
Профиль теперь следует выбранной теме: тёмный, светлый или бежевый.
Общий поиск удалён, поиск внутри модулей сохранён.

ОБНОВЛЕНИЕ GITHUB
Распакуйте все 6 файлов архива в корень сайта с заменой, затем обновите страницу.
Перед обновлением сделайте штатный «Экспорт JSON» текущего планера.
Файлы: index.html, service-worker.js, manifest.webmanifest, две иконки, README.txt.

АККАУНТЫ И СТАРЫЕ ДАННЫЕ
У гостя и каждого аккаунта теперь отдельные данные, история отмены, резерв,
флаг синхронизации и последняя общая версия с облаком. Смена аккаунта закрывает
редакторы, а старые асинхронные ответы не меняют состояние нового пользователя.
Старый ключ artemPlanner.v01 оставлен без изменения как источник до обновления.
Его данные доступны в гостевом режиме; автоматически в другой аккаунт не отправляются.
Если ваши данные до обновления были только локальными: войдите в нужный аккаунт,
откройте Настройки и нажмите «Перенести локальные данные в этот аккаунт».
Оригинал останется на устройстве. При противоречивых записях перенос не выполняется:
сначала экспортируйте нужную версию. Данные из облака загружаются как обычно.
Откат на старый HTML покажет старый источник; новые записи живут в отдельных ключах.
Для переноса данных между версиями используйте Экспорт/Импорт JSON.

СИНХРОНИЗАЦИЯ
Независимые изменения разных записей объединяются по общей версии, включая удаления.
Разные правки одной записи вызывают конфликт: локальная версия не перезаписывается.
В Настройках можно скачать обе версии и явно выбрать источник.
Облачная запись проверяет ожидаемую ревизию version; ревизия увеличивается после записи.
Изменения во время отправки остаются в очереди и отправляются следующим запросом.
При отсутствии известной общей версии конфликт требует явного выбора пользователя.
Старые некорректные форматы не подменяются пустыми данными.

СОХРАНЕНИЕ И ИМПОРТ
Ошибка основной записи откатывает изменения к сохранённому состоянию.
Редактор заметки остаётся открытым при ошибке, включая закрытие по фону.
Повреждённые локальные байты сохраняются: доступны восстановление резерва и импорт.
При блокировке чтения автоматический резерв не заменяется пустым состоянием.
Экспорт повреждённой версии возвращает исходные байты, если хранилище доступно.
Импорт проверяет поддерживаемую схему, структуру записей, IDs, даты, время и числа.
Небезопасные ID/поля отвергаются, атрибуты и цвета в старых рендерах защищены.
Отклонённый импорт не заменяет текущую базу.

ПОДЗАДАЧИ
Подзадачи без даты сохранены; расписание по-прежнему задаётся отдельно.
Пропущенный незавершённый блок можно перенести на следующий день.
«Показать выполненные» открывает завершённые подзадачи, в том числе без даты.
Основной список по умолчанию остаётся без выполненных подзадач.

ОФЛАЙН И ОБНОВЛЕНИЕ
SDK Supabase закреплён на 2.117.1 и кешируется отдельно от версии приложения.
Обновление сервис-воркера удаляет только старые кеши Planner, сохраняет кеш SDK
и не очищает кеши других приложений на том же origin. Ошибка загрузки SDK
не блокирует установку локальной части; до первого успешного кеширования
аккаунт может требовать соединение, локальный планер работает отдельно.

ПРОВЕРКИ И ОСТАВШИЕСЯ ОГРАНИЧЕНИЯ
20 наборов автоматических проверок прошли. Проверены все основные модули,
реальные функции разделения аккаунтов, объединения, удаления/конфликтов,
очереди отправки, CAS, поздних ответов после смены аккаунта, импорта и отката.
Полный JavaScript запускается в DOM-модели с пустой, старой и повреждённой базой.
Тесты используют модели сервиса и DOM. Визуальное наложение на концепт
не выполнено: локальный браузер недоступен, облачный не открывает локальные файлы.
Внешний вид в Safari/iPhone не проверен. Точное пиксельное совпадение не заявляется.
Серверные RLS-политики и живая синхронизация Supabase не проверены:
доступа к серверной конфигурации/пользовательской сессии в этой работе нет.
Новая синхронизация использует уже существующую колонку planner_state.version
и требует серверных прав SELECT, INSERT и UPDATE только своей строки.
Публичный запуск следует проводить после проверки серверных правил доступа
и сценариев двух реальных устройств. Premium пока остаётся статусом профиля.
